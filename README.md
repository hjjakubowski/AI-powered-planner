# AI Powered Planner

AI Powered Planner is a full-stack task and study planning web app. Users can manage projects and tasks, track progress on a Kanban-style dashboard, and ask an AI assistant to suggest a daily plan based on active tasks.

The detailed project report for academic submission is available in [docs/sprawozdanie.md](docs/sprawozdanie.md).

## Features

- User registration, session-based login/logout and account deletion.
- CSRF-protected API requests and role-based access with `USER` / `ADMIN`.
- Project CRUD scoped to the current user.
- Task CRUD with `TODO`, `DOING` and `DONE` statuses.
- Kanban board, list view, filters, search and progress statistics.
- AI chat assistant and daily plan suggestion powered by Google Gemini through Spring AI.
- PostgreSQL persistence.
- Swagger/OpenAPI documentation generated by Springdoc.
- Docker Compose setup for backend, frontend and database.

## Quick Start With Docker

```bash
cp .env.example .env
docker compose up --build
```

After startup:

| Purpose | URL |
| --- | --- |
| Frontend app | `http://localhost:5173` |
| Swagger UI | `http://localhost:8080/swagger-ui.html` |
| OpenAPI JSON | `http://localhost:8080/v3/api-docs` |
| PostgreSQL host port | `localhost:5433` |

If backend dependencies were changed, rebuild the backend image without cache:

```bash
docker compose down
docker compose build --no-cache backend
docker compose up
```

## Local Development

Start PostgreSQL only:

```bash
docker compose up -d postgres
```

Start the backend:

```bash
./gradlew bootRun
```

Start the frontend:

```bash
cd frontend
npm install
npm run dev
```

## Configuration

Important environment variables:

| Variable | Default | Description |
| --- | --- | --- |
| `POSTGRES_DB` | `mydatabase` | PostgreSQL database name in Docker Compose. |
| `POSTGRES_USER` | `myuser` | PostgreSQL user. |
| `POSTGRES_PASSWORD` | `secret` | PostgreSQL password. |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://localhost:5433/mydatabase` | Backend JDBC URL for local runs. |
| `SPRING_DATASOURCE_USERNAME` | `myuser` | Backend database user. |
| `SPRING_DATASOURCE_PASSWORD` | `secret` | Backend database password. |
| `GOOGLE_GENAI_API_KEY` | `disabled` | Google AI Studio API key. `disabled` starts the app without real AI calls. |
| `GOOGLE_GENAI_MODEL` | `gemini-2.5-flash` | Gemini model name. |
| `VITE_API_URL` | `http://localhost:8080/api` | Frontend API base URL. |

Do not commit real secrets. Use `.env` locally and keep `.env.example` as the committed template.

## Authentication Notes

- Login creates a server-side HTTP session.
- The frontend sends cookies with Axios `withCredentials: true`.
- Mutating requests use `X-XSRF-TOKEN`.
- CSRF token is fetched from `GET /api/auth/csrf`.
- API responses use DTOs instead of exposing JPA entities directly.

## Known Limitations

- Hibernate uses `ddl-auto=update` by default; production deployments should use explicit migrations.
- Admin users must be provisioned manually or with a seed/migration.
- Account deletion and email change rely on an active session; a stricter flow could require password confirmation.
- AI responses depend on Gemini availability and API key configuration.
